# Coding Rules — VidCap-Adaptive

- **YAGNI.** Don't build for hypothetical future needs. If the current phase doesn't need it, don't write it.
- **Don't overcomplicate.** Keep code modular, concise, and simple to read. Small functions/files over clever ones.
- **Prefer the simpler approach**, unless the more complicated one is meaningfully more efficient. Simplicity wins ties.
- **No lengthy docstrings.** One or two lines max. If it needs more than that to explain, the code isn't clear enough.
- **Always update `context.md`** in this folder whenever a change affects what it describes (architecture, datasets, deliverables, requirements). Keep it in sync, not stale.
